# Martech AI Stack 五层的本质：一个认知循环

*[English version](five-layers-cognitive-cycle.md)*

Martech AI 的五层不是任意切分，而是把"**数据 → 行动 → 反馈**"这个循环拆解成可独立优化的环节。每一层回答一个不同的认知问题。

| Layer | 它回答什么问题 | 它的产物 | 一句话本质 |
|---|---|---|---|
| **Data** | "用户是谁？发生过什么？" | 可查询的事实记录 | 事实 |
| **Intelligence** | "我们能推断或预测什么？" | 预测分数、概率、向量、因果效应 | 信念 |
| **Decision** | "应该做什么动作？" | 具体的 action 决策 | 选择 |
| **Activation** | "怎样把动作送到用户面前？" | 投放出去的曝光/消息/推送 | 行动 |
| **Measurement** | "它管用吗？我们的信念该怎么更新？" | 因果效果估计、loop 反馈 | 真相 |

## 一一展开

### 1. Data Layer — "事实"

负责回答"发生了什么、谁是谁"。它**只记录、不判断**。

- **拥有**：用户身份图、事件流、同意状态、清洁室
- **动词**：收集、识别、合并、治理
- **典型输出**："用户 X 在 T 时刻看了页面 Y"、"cookie Z 和登录 ID X 是同一个人"
- **失败模式**：身份不一致、事件分类错乱、consent 缺失——**每一层在它之上都会被污染**

### 2. Intelligence Layer — "信念"

把事实加工成对未来或不可见状态的**结构化推断**。

- **拥有**：监督 ML 模型（CTR/CVR/LTV）、因果模型（uplift/DiD）、强化学习策略、embedding 模型、基础模型
- **动词**：预测、估计、嵌入、推断
- **典型输出**："用户 X 转化概率 0.73"、"创意 A 相对创意 B 的 lift 是 1.2×"、"这群人对 push 敏感、对 email 不敏感"
- **失败模式**：过拟合历史、regime shift 漏检、优化错指标（预测 vs 因果用错）

### 3. Decision Layer — "选择"

把信念映射到**单次决策**。这一层是从"我们知道什么"到"我们做什么"的跨越。

- **拥有**：竞价策略、NBA 策略、预算分配、受众选择算法
- **动词**：选择、出价、分配、筛选
- **典型输出**："对这次曝光出价 $0.43"、"周二早 9 点给 cohort Y 发促销 X"、"这季度 Meta 占 35% 预算"
- **失败模式**：贪婪优化、不做反事实推断、缺探索（exploration）、决策粒度和优化目标错配

### 4. Activation Layer — "行动"

把决策**物理送达**用户。这一层本身不优化，它执行。

- **拥有**：付费媒介通道、CRM、push、email、in-app prompt、对话窗口
- **动词**：投放、发送、渲染、对话
- **典型输出**：真实的广告曝光、真实发出的 push、真实展示的对话回应
- **失败模式**：投放失败、延迟、渠道约束没遵守、创意素材没渲染对

### 5. Measurement Layer — "真相"

判断行动**是否真的产生了我们想要的因果效果**，并把结果回灌给 Intelligence 层。

- **拥有**：A/B 实验平台、incrementality 测试、MMM、归因、switchback、合成对照
- **动词**：实验、度量、归因、回测
- **典型输出**："实验组 ROAS=2.3，对照组 1.8，p<0.01"、"MMM 显示 Meta 投入在 500 万后饱和"、"这条 push 的真实净增量约 0.2pp"
- **失败模式**：混淆变量、归因幻觉、p-hacking、缺反事实、把相关当因果

## 为什么是 5 层，不是 3 层或 7 层

这套切分不是任意的——每一层之间的边界都对应一个**不该被混为一谈的概念区分**：

| 边界 | 区分了什么 | 不分的代价 |
|---|---|---|
| Data ↔ Intelligence | 事实 vs 信念 | 把模型预测当成事实存进 CDP，传染下游 |
| Intelligence ↔ Decision | 预测 vs 行动 | 用 CTR 预测直接当出价策略——典型 ML 早期错误 |
| Decision ↔ Activation | 选择 vs 执行 | 投放故障被当作策略问题归因，反过来也一样 |
| Activation ↔ Measurement | 做了 vs 有效 | "我投了所以它有效"——所有归因幻觉的源头 |

每一层都有自己的领域专家、自己的 KPI、自己的失败模式。把它们解耦，才能让一个团队独立优化一个层而不污染另一层。

## 循环关系

```
       ┌───────────── Measurement ──────────────┐
       │             (真相反馈)                  │
       ↓                                         │
   Intelligence ←──── Data ──────                │
       │            （事实供应）                 │
       ↓                                         │
    Decision ──────→ Activation ─────────────────┘
   （选择动作）     （执行动作 → 产生新事实）
```

**Measurement 同时回流到 Intelligence（更新信念）和 Data（产生新的实验事实）。** 这是闭环的本质。一个没有 Measurement 的系统不是 Martech AI 系统，它是单向的发射器。
